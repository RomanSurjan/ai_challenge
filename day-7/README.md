# Day 7: сохранение контекста агента

`day-7` развивает агента из предыдущего дня: CLI и локальный web-чат теперь используют одну и ту же память диалога. После успешного ответа агент сохраняет пару сообщений `user` + `assistant`, а при следующем запуске загружает историю и отправляет новый вопрос в модель вместе с предыдущим контекстом.

## Консилиум экспертов

### Архитектор

Для учебного задания рассматривались JSON и SQLite.

JSON проще: не требует внешних зависимостей, легко читается человеком, удобно проверяется в тестах и достаточно надежен для одной истории диалога. Его слабые места - поиск, конкурентная запись, очистка по условиям и несколько независимых чатов.

SQLite сильнее для будущего расширения: несколько сессий, индексы, поиск по истории, метаданные сообщений, настройки хранения и выборочная очистка естественно ложатся в таблицы. Но для текущего шага SQLite добавит схему, миграции и зависимость от драйвера, что усложнит учебный пример сильнее, чем нужно.

Решение: использовать JSON сейчас, но подключить его через интерфейс `MessageStore`. Так текущая реализация остается простой, а позже хранилище можно заменить на SQLite без переписывания CLI, web-сервера и основной логики агента.

### Backend-разработчик

Память живет не в `main` и не в web-слое, а рядом с `Agent` через интерфейс `MessageStore`. `Agent.Ask` загружает историю перед запросом, добавляет system message и текущий prompt, отправляет полный контекст в DeepSeek, а после успешного ответа сохраняет обновленную историю.

Минимальные изменения:

- `agent.go` - `Agent` получил `Memory MessageStore`, загрузку истории, сборку запроса с контекстом и сохранение только успешного хода;
- `memory.go` - файловое JSON-хранилище с атомарной заменой файла;
- `main.go` - CLI и web создают один и тот же JSON store, путь задается через `-history` или `DAY7_HISTORY_PATH`;
- `server.go` - добавлен `GET /api/history` для технической проверки сохраненной истории.

### QA-инженер

Проверяются сценарии без реальных API-запросов:

- успешный ответ сохраняет `user` и `assistant`;
- новый экземпляр агента загружает историю после перезапуска;
- следующий запрос отправляется в модель вместе с прошлым контекстом;
- при ошибке API незавершенный ход не сохраняется;
- битый файл истории останавливает запрос до обращения к API;
- `GET /api/history` возвращает сохраненные сообщения без реального API-запроса.

### UX/web-разработчик

Web-чат не должен показывать старые сообщения при открытии страницы: интерфейс стартует визуально чистым, чтобы прошлый диалог не дублировался в UI. При этом память все равно подгружается внутри `Agent.Ask`, поэтому следующий web-запрос отправляется в модель вместе с сохраненным контекстом. Endpoint `GET /api/history` оставлен для технической проверки и будущего экрана истории.

## Как устроено хранение

Формат: JSON.

Путь по умолчанию:

```text
day-7/history.json
```

Можно переопределить путь:

```bash
go run ./day-7 -history /tmp/day7-history.json -prompt "Привет"
```

Или через переменную окружения:

```bash
DAY7_HISTORY_PATH=/tmp/day7-history.json go run ./day-7 -prompt "Привет"
```

Файл хранит только историю диалога:

- `user` - сообщения пользователя;
- `assistant` - успешные ответы агента.

System message в историю не записывается: он остается частью конфигурации и добавляется в каждый запрос отдельно.

## Конфигурация

Приложение читает `.env` из корня проекта.

```bash
DEEPSEEK_API_KEY=<ваш DeepSeek API key>
DEEPSEEK_MODEL=deepseek-v4-flash
DEEPSEEK_BASE_URL=https://api.deepseek.com
DAY7_HISTORY_PATH=day-7/history.json
```

Значения по умолчанию:

- endpoint: `https://api.deepseek.com/chat/completions`
- model: `deepseek-v4-flash`
- history: `day-7/history.json`
- timeout: `60s`
- temperature: `0.7`
- max_tokens: `1024`
- thinking: disabled через `{ "type": "disabled" }`

## Запуск

### CLI

Через флаг:

```bash
go run ./day-7 -prompt "Ответь одним предложением: что такое агент с памятью?"
```

Через stdin:

```bash
echo "Объясни простыми словами, зачем агенту история сообщений" | go run ./day-7
```

С отдельным файлом истории:

```bash
go run ./day-7 \
  -history /tmp/day7-history.json \
  -prompt "Меня зовут Роман. Сегодня я изучаю сохранение контекста у агента."
```

### Локальный web-чат

Запуск на адресе по умолчанию `:8080`:

```bash
go run ./day-7 -serve
```

Или через helper-скрипт:

```bash
./day-7/run_web.sh
```

После запуска откройте:

```text
http://localhost:8080
```

Можно выбрать другой адрес:

```bash
go run ./day-7 -serve -addr :8090
```

Web-режим использует тот же `Agent` и тот же `MessageStore`, что и CLI. Страница не отрисовывает прошлые сообщения при открытии, но новые сообщения отправляет через `POST /api/chat`, а агент сам добавляет сохраненный контекст перед обращением к модели.

## Проверка

Автотесты:

```bash
go test ./day-7
```

Ручная проверка перезапуска:

1. Запустить первый запрос:

   ```bash
   go run ./day-7 -prompt "Меня зовут Роман. Сегодня я изучаю сохранение контекста у агента."
   ```

2. Остановить приложение.

3. Запустить второй запрос:

   ```bash
   go run ./day-7 -prompt "Что ты знаешь обо мне из прошлого сообщения?"
   ```

4. Убедиться, что агент отвечает с учетом предыдущего сообщения.

Для web-режима можно отправить первое сообщение в браузере, остановить сервер, снова запустить `go run ./day-7 -serve` и открыть страницу. Старые сообщения не должны появляться в интерфейсе, но следующий вопрос должен получить ответ с учетом сохраненного контекста.
