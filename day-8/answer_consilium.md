# Консилиум по Day 8

Итоговое решение: оставить агента простым и учебным, но добавить локальный слой оценки токенов до обращения к DeepSeek. Реальный `usage` от API сохраняется отдельно, потому что он полезен для сравнения, но приходит только после ответа модели.

## Архитектор

Подсчет токенов вынесен из CLI и web в отдельный модуль. `Agent` остается центральной точкой: он собирает `system + history + current user`, получает локальный `TokenReport`, проверяет лимит контекста и только затем отправляет запрос в API.

## Backend-разработчик

Добавлены:

- приближенный `TokenCounter` без внешних зависимостей;
- `TokenReport` с current/history/system/prompt/answer/total;
- `ContextLimitError`, который останавливает переполненный запрос до API;
- CLI-флаги `-context-limit`, `-demo-tokens`, `-input-price-per-1m`, `-output-price-per-1m`;
- сохранение фактического `usage` DeepSeek рядом с локальной оценкой.

## QA-инженер

Тесты проверяют стабильность токенизатора, успешный token report, отказ без API при переполнении, отсутствие записи в историю на ошибке лимита, чтение `DAY8_*` из окружения, demo-таблицы и JSON-ответ web API.

## UX/web-разработчик

Web-чат не превращен в аналитическую панель. Под ответом показываются только компактные метрики: запрос, история, ответ, всего, лимит и остаток. При переполнении пользователь видит понятное сообщение с теми же цифрами.
