# День 26–27 — локальная LLM и интеграция в веб-приложение

Полноценный многоходовый веб-чат использует локальную модель `qwen2.5:3b`
через Ollama. Облачные LLM API не используются: браузер обращается только к
локальному веб-серверу, а сервер — только к `http://127.0.0.1:11434`.

## Архитектура

```text
Browser
  │ POST /api/chat: системный промт и полная история
  │ ← NDJSON: meta, chunk, ..., done
  ▼
web_server.py — Python standard library, 127.0.0.1:8080
  │ POST http://127.0.0.1:11434/api/chat
  │ stream=true, model=qwen2.5:3b
  ▼
Ollama → локальная qwen2.5:3b
```

Браузер не соединяется с Ollama напрямую. `web_server.py` раздаёт интерфейс,
проверяет входные данные, наличие модели и проксирует поток Ollama в виде
нормализованных NDJSON-событий. Кнопка «Остановить» прерывает запрос и закрывает
исходящий поток.

## Запуск

Требуются Python 3, `curl`, Ollama и установленная модель:

```bash
ollama pull qwen2.5:3b
cd /Users/romansurzhan/ai_challenge/day-26-27
chmod +x run-web.sh
./run-web.sh
```

Откройте `http://127.0.0.1:8080`. Скрипт использует уже работающий Ollama или
запускает `ollama serve` на `127.0.0.1:11434`; при завершении он останавливает
только созданный им процесс. Временный журнал Ollama автоматически удаляется.

Настройки запуска:

```bash
WEB_PORT=8090 ./run-web.sh
OLLAMA_MODEL=qwen2.5:3b ./run-web.sh
OLLAMA_SYSTEM_PROMPT='Отвечай кратко и по-русски.' ./run-web.sh
```

После предварительного запуска Ollama сервер можно запустить напрямую:

```bash
python3 web_server.py --model qwen2.5:3b --port 8080
```

## Возможности

- пользовательский ввод и потоковое отображение ответа;
- многоходовая история: при запросе отправляется весь диалог;
- сохранение истории и системного промта в `localStorage`;
- редактируемый системный промт, передаваемый первым сообщением;
- остановка генерации, новый чат и статус локального Ollama;
- безопасный вывод текста и fenced-блоков кода без `innerHTML`;
- адаптивный интерфейс и понятные сообщения об ошибках.

История находится только в текущем браузере. Сервер не ведёт учётные записи и
не сохраняет разговоры на диск. При обновлении с прежней версии интерфейс один
раз переносит историю из старого ключа `localStorage`.

## Ограничения

| Ограничение | Значение |
|---|---:|
| HTTP-тело запроса | 256 KiB |
| Одно сообщение | 12 000 символов |
| Системный промт | 4 000 символов |
| История | 64 сообщения |
| Вся история | 60 000 символов |
| Служебный JSON Ollama | 2 MiB |
| Одна строка потока Ollama | 256 KiB |
| Проверка соединения | 5 секунд |
| Ожидание генерации | 180 секунд |

Сервер принимает чередующуюся историю `user → assistant`, начинающуюся и
заканчивающуюся сообщением пользователя. Некорректный JSON, неверные типы,
пустые и слишком длинные сообщения отклоняются до генерации. Компактная модель
`qwen2.5:3b` может ошибаться, а интерфейс намеренно не реализует полный Markdown,
HTML, подсветку синтаксиса и формулы.

## Тесты и проверки синтаксиса

```bash
cd /Users/romansurzhan/ai_challenge/day-26-27
python3 -m unittest discover -s tests -v
python3 -m py_compile web_server.py tests/test_web_server.py
node --check web/app.js
bash -n run-web.sh
```

Серверные тесты используют временный поддельный Ollama и не требуют сети или
реальной модели. Они проверяют многоходовую историю и системный промт,
потоковые события, валидацию, ошибку Ollama и отсутствие модели.
