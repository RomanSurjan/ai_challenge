# День 29 — оптимизация локальной LLM

Итоговый текстовый отчёт по ранее выполненным измерениям. Сырые результаты,
логи и материалы демонстрации удалены; упомянутые артефакты можно получить
повторным локальным прогоном, они исключены из Git.

10 октября 2026, Europe/Moscow. Apple M1 Pro, 16 GiB unified memory; Ollama 0.35.0; Go 1.26.1 darwin/arm64. Все generation/embeddings/judge локальны. Полный read-only индекс Day21 по Дням 16–20.

Содержательного улучшения на tuning-наборе не получено. Поэтому baseline остаётся рекомендацией для использования. «После» — замороженный экспериментальный кандидат для честного итогового сравнения, а не заранее объявленный победитель. Ни один новый профиль не объявлялся качественным по accepted rate.

## Профили и выбор

Baseline воспроизводит финальный Day28: qwen2.5:3b, Q4_K_M, t0, seed0, 512 tokens, ctx32768, исходные prompt/schema/validator и один repair. Паритет сообщений/schema подтверждён с историческим q03: baseline-parity.json. Исторические latency не использованы для итоговой пары.

Кандидат «После»: qwen2.5:3b / Q4_K_M, t0, seed0, 768 tokens, ctx16384, prompt technical-v5. LLM выводит claims/evidence/status/clarification; текст со ссылками собирается из claims, затем проходит прежние проверки exact quotes и source IDs. 1–3 утверждения и частичный ответ разрешены. Источники и цитаты не ослаблены. В исходном контракте сохранено историческое отсутствие обязательной проверки каждого inline ID; новый renderer выдаёт ID для всех claims.

Выбор зафиксирован **до** control: selection-frozen.json. 768 завершает некоторые JSON, которые обрывались на 512; 1024 не улучшил содержание. 8192 не вместил длинный tuning-запрос; 16384 вмещает все tuning input/repairs и использует меньше loaded model memory. t0 сохранён: принятый ответ t0.2 оказался нерелевантным и с неподтверждёнными claims. Q8 дал точные цитаты, но не объяснил защиту пути и ошибочно приписал Artifact MCP роль оркестратора.

## Экспериментальный протокол

До ответов сохранены [tuning](eval/tuning.json), отдельный [control](eval/control.json), [regression](eval/regression.json), [protocol](eval/protocol.json). Три tuning-вопроса: Decimal, Artifact sandbox, длинная session history. Кандидаты меняют один фактор относительно опорной конфигурации, полного декартова перебора нет. Дополнительные версии prompt исправляют выявленные ошибки до control; исходный план и amendments сохранены. Generator читает только ID/question; эталоны и оценки ему не передаются.

Итоговая пара измерена заново в одной сессии: regression 14×2 ветки, control 6 вопросов ×3 повтора ×2 ветки. Warmup отдельно, не в latency. Три повтора каждого вопроса последовательны; порядок AB/BA чередуется и внутри вопроса, и между вопросами. Retrieval один раз на пару, полные chunks/порядок/IDs одинаковы. Repairs имеют собственные prompts. Настройки после control не подгонялись.

Judge одинаков: Qwen2.5 3B Q4, t0 seed0, 128 tokens, ctx32768; оценка вспомогательная. Correctness и completeness оцениваются отдельно: 0 неверно/нерелевантно/не раскрыто, 1 частично, 2 корректно/достаточно полно. Обоснованный no-data refusal получает 2/2; ложный отказ 0/0. Grounding — отдельная ручная проверка связи quote→claim. [Разбор каждого control-ответа](eval/review-control.json), [regression](eval/review-regression.json), [tuning](eval/review-tuning.json).

## Проверка окна
Exact /tokenize уже загруженного matching model blob runner, локально по 127.0.0.1; ChatML проверен на 16 pilot calls с нулевой разницей против prompt_eval_count, далее равенство проверяется на каждом exact-tokenized ответе. Резервируется весь num_predict; repair считается заново. Если runner/ps недоступен, fallback UTF-8 byte-BPE bound+256 явно записан, может отклонить fitting input. Никакого незаметного сокращения контекста. При первом control-pilot обнаружена вариация cosine до 0.00067 между uncached/repeated embedding: IDs/text/order совпали. Для итоговых повторов сохраняется полный первый snapshot, свежий retrieval выполняется и измеряется заново, записан отдельно, а генераторы всегда видят первый snapshot. Это исправление измерительного конвейера при неизменных профилях, prompt, порогах и questions. [Amendment](eval/protocol-measurement-amendment.json). Pilot `control-pilot-drift.json` сохраняет первый pair; raw второго pair потерян из-за прежнего checkpoint после guard. Он не восстановлен выдуманными данными и не включён в итог. Финальная серия полностью повторена. 8192 непригоден для длинного tuning input; такой вызов не отправляется. Калибровка, audit. Метод зависит от внутреннего endpoint и ChatML установленной версии.

## Ограничения и итог
Малые tuning/control наборы, один tuning-повтор, только три control-повтора; уверенный статистический вывод о превосходстве невозможен. Retrieval фиксирован и иногда не находит детали реализации: модель не должна восполнять их догадкой. Exact citation — происхождение, а не entailment; локальный judge может ошибаться. Содержательная полнота требует отдельной оценки. Tuning не оправдал замену baseline; tradeoff кандидата — меньше профильное окно и компактнее output при новых ложных отказах. Рекомендация baseline сохранена до control; настройка под control не выполнялась.
